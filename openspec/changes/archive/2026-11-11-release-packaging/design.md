# Design

## Context

See proposal.md for the motivation. What exists today:

- `apps/desktop/tauri.conf.json`: product VoiceBro, version 0.2.0, identifier
  `com.voicebro.desktop`, `bundle.targets: ["nsis"]`, an icon, no `bundle.windows.nsis`
  section, no resources, no license. `apps/desktop/Cargo.toml` has version 0.2.0 (the
  build stamp reads it); the other crates are internal at 0.1.0. No tag exists.
- The installed Tauri bundler (2.10.4) NSIS template: `installMode` currentUser installs
  into `$LOCALAPPDATA\${PRODUCTNAME}` with a directory page and `RequestExecutionLevel
  user`; perMachine uses Program Files with admin. A license page appears only when a
  license is configured. The finish page offers "Run" and a desktop shortcut. An existing
  install shows a reinstall page; an update run passes `/UPDATE` to the old uninstaller.
  The uninstaller removes the installed files, shortcuts and registry entries, then
  `RMDir "$INSTDIR"` (only when empty); its "Delete the application data" checkbox removes
  `$APPDATA\com.voicebro.desktop` and `$LOCALAPPDATA\com.voicebro.desktop` only, skipped
  when `$UpdateMode = 1`; `NSIS_HOOK_POSTUNINSTALL` runs after that, with
  `$DeleteAppDataCheckboxState` and `$UpdateMode` in scope. `bundle.windows.nsis`
  accepts `installMode`, `languages`, `displayLanguageSelector`, `startMenuFolder`,
  `installerHooks` and others.
- The app's data directory is the executable's folder (`paths.rs`), overridable by
  `VOICEBRO_DATA_DIR`; the Discord token is the generic credential
  `VoiceBro/discord_token` (`secrets.rs`). Nothing in shipped code uses `temp_dir`, `dirs`
  or Tauri's app directories (inventory of 2026-11-11).
- The bot uses the intents `GUILDS | GUILD_VOICE_STATES` only, no privileged intent
  (`discord/mod.rs`), which the README needs.
- `apps/desktop/Cargo.toml` already depends on `windows-sys` for the memory reading.

## Goals / Non-Goals

**Goals:**

- One command that turns a tagged `main` into the three release files, and refuses
  anything else.
- An uninstall that can leave the machine clean, and an update that never loses data.
- A README that a person new to all three services can follow.

**Non-Goals:**

- Code signing (postponed by the user; `bundle.windows.signCommand` or a thumbprint can be
  added later without changing this design).
- An auto-updater, an MSI, a Microsoft Store package.
- Publishing the GitHub release itself: that is an outward action the user approves when
  the time comes (Workflow follow-up).
- Bundling Vosk models (downloads on first use, change `wake-languages`).

## Decisions

### D1. NSIS configuration

```json
"bundle": {
  "targets": ["nsis"],
  "resources": { "../../LICENSE": "LICENSE.txt",
                 "../../target/release/dist-notices/THIRD-PARTY-NOTICES.txt": "THIRD-PARTY-NOTICES.txt" },
  "windows": { "nsis": {
    "installMode": "currentUser",
    "languages": ["English", "Russian"],
    "displayLanguageSelector": false,
    "startMenuFolder": "VoiceBro",
    "installerHooks": "installer-hooks.nsh"
  } }
}
```

No license page: the MIT license asks for no acceptance; the license and the notices are
installed as files. With the selector off, NSIS takes the system language when it is one
of the two. The notices file is generated by the release script before `cargo tauri
build` (D4), so the bundle always carries the current list.

Alternative considered: `perMachine` or `both`. Rejected: the app writes next to its
executable, and Program Files is not writable without elevation.

### D2. The uninstall hook

`apps/desktop/installer-hooks.nsh` defines `NSIS_HOOK_POSTUNINSTALL`, which acts only when
`$DeleteAppDataCheckboxState = 1` and `$UpdateMode <> 1` (the same guard as Tauri's own
deletion): `RMDir /r` on `logs`, `assets`, `models`, `codex-workspace`, `webview-data`,
`Delete` on `settings.json` and `settings.json.tmp`, `nsExec::Exec 'cmdkey
/delete:VoiceBro/discord_token'`, then `RMDir "$INSTDIR"`. A reinstall over an older
version runs the old uninstaller silently, where the box is not checked, so the data
stays. Whether `cmdkey /delete` removes this generic credential is checked live in task
3.3 before relying on it; if it does not, the hook calls the app itself with a
`--forget-secrets` flag that deletes it through `secrets.rs`. (Checked on a throwaway
generic credential: `cmdkey /delete:<target>` removes it, so no flag is needed.)

The same file defines `NSIS_HOOK_POSTINSTALL`, found during the installer tests: with two
languages and no selector, Tauri's template stores the chosen language nowhere, and its
uninstaller (`MUI_UNGETLANGUAGE`) then opens an "Installer Language" dialog before
anything else. The hook writes `$LANGUAGE` to `HKCU\${MANUPRODUCTKEY}\Installer Language`,
where the uninstaller reads it; Tauri's own deletion of the data removes that value.

### D3. The writable check

First thing in `main()` of the desktop app, before logging and Tauri: create and delete
`<data dir>\.voicebro-write-test`. On failure, `MessageBoxW` (feature
`Win32_UI_WindowsAndMessaging` of `windows-sys`) with "VoiceBro cannot write to
<folder>. Install or extract VoiceBro into a folder you can write to, for example
%LOCALAPPDATA%\VoiceBro." and exit code 1. The check is a function of the directory, so a
unit test can run it on a folder whose write permission is denied with `icacls`.

### D4. The release script

`scripts\build-release.ps1 [-Trial]`:

1. Reads the version from `apps/desktop/tauri.conf.json` and checks that
   `apps/desktop/Cargo.toml` has the same.
2. Without `-Trial`: refuses unless the branch is `main`, `git status --porcelain` is
   empty and `HEAD` carries the tag `v<version>`.
3. Prepends the VS Build Tools CMake to `PATH` (as `AGENTS.md` says).
4. Runs `scripts\third-party-notices.ps1` into `target\release\dist-notices\`.
5. Runs `cargo tauri build` in `apps/desktop`.
6. Writes into `target\release\dist\` (or `dist-trial\`): the installer
   `VoiceBro_<version>_x64-setup.exe`, the zip `VoiceBro_<version>_x64-portable.zip`
   (`voicebro.exe`, `README.md`, `LICENSE`, `THIRD-PARTY-NOTICES.txt`) and
   `SHA256SUMS.txt`. Trial outputs carry `-trial` in their names.

Everything stays inside the project folder (`target\`), nothing in a system temp folder.

### D5. Third-party notices without a new tool

`scripts\third-party-notices.ps1` runs `cargo metadata --format-version 1
--filter-platform x86_64-pc-windows-msvc`, walks the resolved graph from
`voicebro-desktop` over normal dependencies (not dev, not build), and for each package
writes its name, version, license expression, repository and the text of every
`LICENSE*`, `COPYING*` and `NOTICE*` file in its manifest directory. Packages without such
a file get their license expression and repository link. A fixed tail names Vosk 0.3.45
(Apache-2.0) and the two catalog models (Apache-2.0) as downloaded components.

Alternative considered: `cargo-about`. Rejected: a new tool to install for one file.

### D6. The README

English, in the repository root, also in the zip. Its facts come from the code at the
time of writing: the intents (no privileged intent to enable), the slash commands, the
default hotkey, the settings and their tabs, the data folder's contents, the Codex
version the app was tested with, and the steps of `wake-languages` and
`codex-onboarding`. Discord's portal steps are written against the portal as it is when
the task runs and marked with that date.

### D7. Version 1.0.0

`apps/desktop/Cargo.toml` and `tauri.conf.json` become 1.0.0 in this change. The tag
`v1.0.0` is set on `main` after the merge, with the user's OK, and the release script runs
from it.

## Risks / Trade-offs

- [The build is unsigned: SmartScreen warns and Windows shows an unknown publisher] → the
  README explains "More info → Run anyway" and the checksums; signing is a later change.
- [A portable copy and an installed copy share the token's Credential Manager entry] →
  deleting the data in one uninstall removes the other's token; the README says so.
- [WebView2 missing on an old Windows 10] → the installer's default bootstrapper installs
  it; the README tells zip users where to get the WebView2 Runtime.
- [The user installs into a protected folder they chose] → the writable check stops the
  app with a clear message (D3).
- [Notices miss a crate added later] → the script reads the graph at every release build.

## Migration Plan

Users of builds before 1.0.0 ran the app from `target\` or a copied folder; they install
1.0.0 into a new folder and copy `settings.json` over if they want their settings (the
README's update section says so). Rollback: uninstall without deleting the data and run an
older build from its folder.
